Part 1.1: Convolutions from Scratch

Four for loops

First, I get the kernel size. Then I pad the image, surrounding it with zeros so the kernel always has something to read at the edges. Next, I work out the output size: the kernel can sit at (padded size − kernel size + 1) positions along each axis, which in "same" mode gives an output the same size as the original image. I make an empty output of that size. The two outer loops then pick an output pixel (r, c), so every pixel gets visited one at a time. For each pixel, I start a running total at 0 and use the two inner loops to walk over every cell (i, j) of the kernel. At each cell, I multiply the image value padded[r + i, c + j] by the kernel value kernel[kernel_height - 1 - i, kernel_width - 1 - j] and add it to the total. Reading the kernel backwards like this is what flips it, which turns the operation from cross-correlation into convolution. Once the inner loops finish, I store the total in output[r, c] and move on to the next pixel. Since every multiply-add is its own Python step, this version does 81 operations per pixel for the 9x9 box filter and 3 for Dx and Dy, which is why it's the slowest of the three on the 9x9 box filter. 

def convolution_four(image, kernel, mode="same"):
    kernel_height, kernel_width = kernel.shape
    padded = pad_image(image, kernel, mode)
    output_height, output_width = padded.shape[0] - kernel_height + 1, padded.shape[1] - kernel_width + 1
    output = np.zeros((output_height, output_width))
    for r in range(output_height):
        for c in range(output_width):
            pixel_sum = 0.0
            for i in range(kernel_height):
                for j in range(kernel_width):
                    pixel_sum += kernel[kernel_height - 1 - i, kernel_width - 1 - j] * padded[r + i, c + j]
            output[r, c] = pixel_sum
    return output

Two for loops

Getting the kernel size, padding the image, and working out the output size are the same as before. The difference starts with the flip: instead of reading the kernel backwards inside the loops, I flip it once up front with kernel[::-1, ::-1], which reverses its rows and columns. I make the empty output and use the same two loops to pick each output pixel (r, c). But instead of walking the kernel one cell at a time, I grab the entire kernel_height × kernel_width window under the kernel in one slice, padded[r : r + kernel_height, c : c + kernel_width], multiply it elementwise with the flipped kernel, and sum the result with np.sum. This gives exactly the same value as the four-loop version, since flipped[i, j] is kernel[kernel_height - 1 - i, kernel_width - 1 - j]. I store it in output[r, c] and return the output once every pixel is filled. Replacing the two inner loops with one numpy call moves the multiply-adds into numpy's compiled code, which is why this version is much faster on the 9x9 box filter. 

def convolution_two(image, kernel, mode="same"):
    kernel_height, kernel_width = kernel.shape
    padded = pad_image(image, kernel, mode)
    output_height, output_width = padded.shape[0] - kernel_height + 1, padded.shape[1] - kernel_width + 1
    flipped = kernel[::-1, ::-1]
    output = np.zeros((output_height, output_width))
    for r in range(output_height):
        for c in range(output_width):
            output[r, c] = np.sum(padded[r : r + kernel_height, c : c + kernel_width] * flipped)
    return output

Padding

When the kernel sits near the edge of the image, part of it hangs off the image, so I pad the image with zeros first to give it something to read. I used "same" padding for my results, which adds just enough zeros that the output is the same size as the input: half the kernel size on each side, so 4 pixels for the 9x9 box filter and 1 pixel for Dx and Dy. I also implemented "full" padding, which adds kernel size − 1 on every side so the output grows by kernel size − 1 in each direction. The function takes care of both modes with np.pad, which fills with zeros by default. This is the same as convolve2d with boundary="fill", fillvalue=0, and it's why the edges of the blurred image get slightly darker and the derivative images show a false edge along the border, since the padding acts like black pixels. 

def pad_image(image, kernel, mode="same"):
    kernel_height, kernel_width = kernel.shape
    if mode == "same":
        pad_widths = ((kernel_height // 2, (kernel_height - 1) // 2), (kernel_width // 2, (kernel_width - 1) // 2))
    else:
        pad_widths = ((kernel_height - 1, kernel_height - 1), (kernel_width - 1, kernel_width - 1))
    return np.pad(image, pad_widths)

Comparison with scipy.signal.convolve2d

Both of my implementations match convolve2d: after rounding to 2 decimal places, np.array_equal returns true for all three filters, which confirms that my flip and padding are correct.

For runtime, on the 9x9 box filter the two-loop version (3.02 s) is about 8x faster than the four-loop version (23.99 s), because it replaces 81 Python multiply-adds per pixel with one numpy call. SciPy (0.15 s) is another 20x faster than that, since it runs entirely in compiled code with no Python loops at all. For Dx and Dy the ranking flips: the four-loop version (about 1.5–1.7 s) is faster than the two-loop version (about 2.9 s). With only 3 multiplies per pixel, there is very little work to save by vectorizing, while each np.sum call still has a fixed overhead. That's also why the two-loop time is about 3 s no matter which filter I use. Vectorizing only pays off when the kernel is big enough to make up for that overhead. 

def timed(function, *args, **kwargs):
    start = time.perf_counter()
    result = function(*args, **kwargs)
    return result, time.perf_counter() - start


for name, kernel in [("boxblur", box_filter_9x9), ("Dx", Dx), ("Dy", Dy)]:

Part 1.2: Finite Difference Operator

I convolved the cameraman image with Dx = [1, 0, -1] and Dy = [1, 0, -1]T using scipy.signal.convolve2d to get the partial derivatives in x and y, then combined them into the gradient magnitude, sqrt((∂f/∂x)2 + (∂f/∂y)2), which is large wherever the brightness changes quickly in any direction.

Edge image and threshold

To turn the gradient magnitude into an edge image, I kept only the pixels above a threshold. I tried thresholds from 30 to 135 and chose 75. At 45 the grass is full of noise, and at 120 the outline of the coat and the tripod legs break apart, so 75 is the best tradeoff between removing noise and keeping the real edges.

Part 1.3: Derivative of Gaussian (DoG) Filter

Gaussian filter

I built a 1D Gaussian with cv2.getGaussianKernel using sigma = 2 and a size of 6 * sigma + 1 = 13, following the rule from lecture that the filter's half-width should be about 3 sigma. I then took its outer product with its transpose to get the 2D Gaussian. 

sigma = 2
gaussian_1d = cv2.getGaussianKernel(6 * sigma + 1, sigma)
gaussian_2d = gaussian_1d @ gaussian_1d.T

Method 1: blur, then differentiate

I blurred the cameraman image with the Gaussian, then convolved the blurred image with Dx and Dy and computed the gradient magnitude the same way as in Part 1.2. 

def convolve(image, kernel):
    return convolve2d(image, kernel, mode="same", boundary="symm")


blurred = convolve(img, gaussian_2d)
blurred_x, blurred_y = convolve(blurred, Dx), convolve(blurred, Dy)
blurred_magnitude = np.sqrt(blurred_x ** 2 + blurred_y ** 2)

I chose a threshold of 20. At 8, the edge image picks up fine background detail like the tall tower and the full row of buildings, but the grass turns into dense speckle, so blurring alone isn't enough at that level. At 32, the grass is clean, but real edges start disappearing: the horizon breaks into short dashes, the tower is gone, and the tripod legs split into disconnected pieces. At 20, the grass stays clean while the cameraman, camera, tripod, and horizon remain mostly continuous. The tradeoff is that the faint background tower mostly drops out, which I accepted to avoid the grass noise.

Method 2: DoG filters

I convolved the Gaussian with Dx and Dy to get two derivative of Gaussian (DoG) filters. With these, the image needs only one convolution per direction instead of two. This works because convolution is associative: blurring and then differentiating is the same as convolving once with the blurred derivative filter. 

dog_filter_x, dog_filter_y = convolve2d(gaussian_2d, Dx), convolve2d(gaussian_2d, Dy)

dog_magnitude = np.sqrt(convolve(img, dog_filter_x) ** 2 + convolve(img, dog_filter_y) ** 2)

Comparison with the finite difference method

The 1.3 edge image is a lot cleaner than 1.2. In 1.2, the grass shows up as noise because the finite difference picks up every small change between neighboring pixels. In 1.3, the Gaussian blurs those small changes out first, so only the bigger edges like the cameraman and tripod are left. The edges are also thicker in 1.3 because the blur spreads each sharp edge out over a few pixels, so the gradient is high over a wider area. Since the blur makes all the gradient values smaller, I also had to lower the threshold from 75 to 20. The downside is that the blur also removes small details, like the tower in the background.

Part 2.1: Image Sharpening

How unsharp masking works

The Gaussian is a low-pass filter, so blurring an image keeps only its low frequencies. I subtracted the blurred image from the original, which leaves just the high frequencies, and then added alpha times those high frequencies back to the original to sharpen it. I used the same Gaussian (sigma = 2) as in Part 1.3.

Because convolution is linear, I combined all of this into a single filter: f + alpha(f − f * g) = f * ((1 + alpha)e − alpha g), where f is the image, g is the Gaussian, and e is the unit impulse (identity). This is the unsharp mask filter from lecture. 

identity = np.zeros_like(gaussian_2d)
    identity[3 * sigma, 3 * sigma] = 1

    blurred = convolve(img, gaussian_2d)
    high_frequencies = img - blurred

    for alpha in [0, 1, 2, 5, 10]:
        unsharp_filter = (1 + alpha) * identity - alpha * gaussian_2d
    sharpened = convolve(img, unsharp_filter)

Part 2.2: Hybrid Images

How hybrid images work

Up close, the high frequencies of an image dominate what I see, but from far away only the low frequencies are visible. A hybrid image uses this to show one picture up close and a different one from a distance. I low-pass filtered one image with a Gaussian, high-pass filtered the other by subtracting its Gaussian blur from the original, and added the two together. Before filtering, I aligned each pair by clicking two matching points in both images. 

def low_pass(im, sigma):
    gaussian_1d = cv2.getGaussianKernel(6 * sigma + 1, sigma)
    blurred = convolve2d(im, gaussian_1d, mode="same", boundary="symm")
    return convolve2d(blurred, gaussian_1d.T, mode="same", boundary="symm")

def high_pass(im, sigma):
    return im - low_pass(im, sigma)

def hybrid_image(im1, im2, sigma1, sigma2):
    return high_pass(im1, sigma1) + low_pass(im2, sigma2)

Part 2.3: Gaussian and Laplacian Stacks

Building the stacks

A stack is like a pyramid, but it is never downsampled, so every level is the same size as the original image. For the Gaussian stack, I apply the same Gaussian blur at each level (as the assignment says, "just apply the Gaussian filter at each level, but do not subsample"). Each Laplacian level is one Gaussian level minus the next, and the last level is the blurriest Gaussian level, so all the levels add back up to the original. I used 5 levels and sigma = 5. 

levels = 5
sigma = 5


def gaussian_blur(image, sigma):
    gaussian_1d = cv2.getGaussianKernel(6 * sigma + 1, sigma)
    blurred = convolve2d(image, gaussian_1d, mode="same", boundary="symm")
    return convolve2d(blurred, gaussian_1d.T, mode="same", boundary="symm")


def gaussian_stack(image):
    stack = [image]
    for i in range(levels - 1):
        stack.append(gaussian_blur(stack[-1], sigma))
    return stack


def laplacian_stack(gaussian):
    return [gaussian[i] - gaussian[i + 1] for i in range(levels - 1)] + [gaussian[-1]]

Part 2.4: Multiresolution Blending

How the blending works

I reuse the Gaussian and Laplacian stacks from Part 2.3. Each image gets a Laplacian stack and the mask gets a Gaussian stack. I blend each level as level1 * mask + level2 * (1 − mask), using the mask from the same level, and then sum all the levels. This way the fine details get a sharp seam and the broad colors get a soft one. I used 8 levels and sigma = 20 for the balls, and 5 levels and sigma = 5 for Jordan and LeBron. 

def gaussian_stack(image, levels, sigma):
    stack = [image]
    for i in range(levels - 1):
        stack.append(gaussian_blur(stack[-1], sigma))
    return stack


def blend(im1, im2, mask, levels, sigma):
    im1_laplacian, im2_laplacian = laplacian_stack(gaussian_stack(im1, levels, sigma)), laplacian_stack(gaussian_stack(im2, levels, sigma))
    mask_gaussian = gaussian_stack(mask, levels, sigma)
    im1_masked = [level * m for level, m in zip(im1_laplacian, mask_gaussian)]
    im2_masked = [level * (1 - m) for level, m in zip(im2_laplacian, mask_gaussian)]
    blended_levels = [a + b for a, b in zip(im1_masked, im2_masked)]
    return im1_masked, im2_masked, blended_levels

What I learned

The most important thing I learned is how blending works by blurring and then regenerating the image. Blurring the images over and over splits them into layers from fine details to broad colors, and blurring the mask lets each layer get its own seam: sharp for the details and soft for the colors. Adding the blended layers back together regenerates one image where the seam is hard to see, which is how Jordan ends up looking like he's actually behind LeBron.
